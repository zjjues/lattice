# Step 02: AIS Sample App 静态分析

## 本步骤目标

本步骤静态阅读 `external/sample-app-ais-integration-rest` 公开示例项目，理解它如何把本地 AIS 船舶数据转换为 Lattice-style entity，并通过 `Lattice.entities.publish_entity` 发布到 Lattice。

本步骤只做代码阅读和文档总结，不运行真实 Anduril API 调用，不要求 Lattice token，不修改 Anduril sample app 源码。

## 为什么选择 sample-app-ais-integration-rest

该示例项目与当前本地 entity generator 的目标最接近：

- 数据对象同样是 `Surface Vessel` / 船舶目标。
- 输入数据来自 AIS，包含 MMSI、经纬度、船名等字段。
- 输出路径是 Lattice entity。
- 代码中明确展示了 entity payload 的构造方式。
- 代码中明确调用了 `Lattice.entities.publish_entity`。

因此它适合作为第 1 步本地 generator 后续对齐 Lattice publish 形状、字段命名和本地 mock API 的参考。

`README.md` 的主要说明：

- 这是一个 Python REST integration 示例，用模拟 AIS vessel traffic data 向 Lattice 发送数据。
- 示例展示了如何创建 entity JSON payload，并调用 `Lattice.entities.publish_entity` 发布 entity。
- AIS 数据集中本示例关注 4 个字段：`MMSI`、`LAT`、`LON`、`VesselName`。
- 运行前需要安装 Python 3.9 或更高版本，并完成 Lattice SDK setup。
- 配置文件是 `var/config.yml`，其中包含 Lattice endpoint、client id、client secret、sandboxes token、发布频率、跟踪的 MMSI 列表和 AIS 数据生成间隔。
- 运行命令是 `python src/main.py --config var/config.yml`。

## 关键文件说明

### `src/main.py`

Python 程序入口是 `src/main.py` 中的：

```python
if __name__ == "__main__":
```

它完成以下工作：

- 用 `argparse` 读取 `--config` 参数。
- 用 `yaml` 读取配置文件。
- 用 Pydantic `Config` 模型解析配置。
- 创建 `AIS(logger, DATASET_PATH, cfg.vessel_mmsi)`。
- 创建真实 `Lattice(...)` client。
- 创建 `AISLatticeIntegration(logger, client, ais_data)`。
- 用 `BackgroundScheduler` 周期执行：
  - `ais_data.refresh_ais`
  - `ais_lattice_integration_hook.publish_vessels_as_entities`

静态分析时不要运行该文件，因为它会根据配置创建真实 Lattice client，并在定时任务里调用发布逻辑。

### `var/config.yml`

配置项包括：

| 配置项 | 用途 |
| --- | --- |
| `lattice-endpoint` | Lattice API endpoint |
| `sandboxes-token` | Sandbox authorization header token |
| `lattice-client-id` | Lattice client id |
| `lattice-client-secret` | Lattice client secret |
| `entity-update-rate-seconds` | entity 发布间隔 |
| `vessel-mmsi` | 要跟踪的船舶 MMSI 列表 |
| `ais-generate-interval-seconds` | AIS 数据刷新间隔 |

该项目没有使用 `.env`。凭据通过 `var/config.yml` 读取。当前仓库里的文件是占位符，例如 `<LATTICE_ENDPOINT>`、`<SANDBOXES_TOKEN>`、`<YOUR_CLIENT_ID>`、`<YOUR_CLIENT_SECRET>`。

### `var/ais_vessels.csv`

AIS 数据文件是 `var/ais_vessels.csv`。CSV 包含多列，例如：

- `MMSI`
- `BaseDateTime`
- `LAT`
- `LON`
- `SOG`
- `COG`
- `Heading`
- `VesselName`
- `IMO`
- `CallSign`
- `VesselType`

但示例代码只读取：

- `MMSI`
- `LAT`
- `LON`
- `VesselName`

### `src/ais.py`

`AIS` 类负责把 CSV 数据转换成按 MMSI 分组的迭代器，并维护一个缓存：

- `pd.read_csv(self.csv_path, usecols=["MMSI", "LAT", "LON", "VesselName"])`
- `self.grouped_data`：按 `MMSI` 分组，每个 MMSI 对应一个迭代器。
- `self.cached_ais`：保存每个被请求 MMSI 的最新一条 AIS 数据。
- `refresh_ais()`：为每个 MMSI 读取下一条记录，并更新缓存。
- `get_all_data()`：返回当前缓存中的 vessel 数据列表。

Vessel 数据结构是：

```python
VesselData = namedtuple("VesselData", ["MMSI", "LAT", "LON", "VesselName"])
```

### `src/integration.py`

entity payload 的核心构造逻辑在 `AISLatticeIntegration.publish_vessels_as_entities()` 中。它遍历 `self.ais.get_all_data()`，对每条 `vessel_data` 调用：

```python
self.lattice.entities.publish_entity(...)
```

这里不是先构造一个普通 dict 再发送，而是用 Anduril SDK 的对象和参数构造 entity，例如 `Aliases`、`MilView`、`Location`、`Position`、`Ontology`、`Provenance`。

## AIS 到 Entity 的数据流

```text
var/ais_vessels.csv
  ↓
AIS.__init__()
  - pandas 读取 MMSI / LAT / LON / VesselName
  - 按 MMSI groupby
  - 为每个 MMSI 创建迭代器
  ↓
AIS.refresh_ais()
  - 周期性取每个 MMSI 的下一条 AIS 记录
  - 写入 cached_ais
  ↓
AIS.get_all_data()
  - 返回当前缓存的 VesselData 列表
  ↓
AISLatticeIntegration.publish_vessels_as_entities()
  - 读取 MMSI、VesselName、LAT、LON
  - 构造 Lattice-style entity 字段
  ↓
Lattice.entities.publish_entity(...)
  - entity_id
  - aliases
  - mil_view
  - location
  - ontology
  - provenance
  - data_classification
  ↓
Lattice
```

## `publish_entity` 在哪里调用

调用位置：

```text
external/sample-app-ais-integration-rest/src/integration.py
```

具体方法：

```python
AISLatticeIntegration.publish_vessels_as_entities()
```

调用形状：

```python
entity = self.lattice.entities.publish_entity(
    entity_id=str(vessel_data.MMSI),
    description="Generated by AIS Vessel Traffic Dataset",
    is_live=True,
    created_time=datetime.now(timezone.utc).isoformat(),
    expiry_time=(datetime.now(timezone.utc) + timedelta(seconds=10)).isoformat(),
    aliases=Aliases(...),
    mil_view=MilView(...),
    location=Location(...),
    ontology=Ontology(...),
    provenance=Provenance(...),
    data_classification=Classification(...),
)
```

发布任务由 `src/main.py` 里的 APScheduler 定时触发：

```python
scheduler.add_job(
    lambda: run(ais_lattice_integration_hook.publish_vessels_as_entities()),
    "interval",
    seconds=cfg.entity_update_rate_seconds,
)
```

## 和第 1 步 Entity Generator 的字段对照

第 1 步 `generate_entities.py` 输出的是本地 JSON / JSONL，字段使用 camelCase。AIS sample app 使用 Anduril SDK 调用参数，Python 层字段多为 snake_case，SDK 发送时可理解为对应的 Lattice entity 字段。

| 重点字段 | AIS sample app | 第 1 步 generator | 对照结论 |
| --- | --- | --- | --- |
| `entityId` | `entity_id=str(vessel_data.MMSI)` | `entityId: sim-surface-vessel-0001` | 两者都有唯一 ID。sample 使用真实 AIS `MMSI`；generator 使用本地模拟编号。后续可增加 MMSI 风格 ID 或 `alternateIds`。 |
| `aliases.name` | `aliases=Aliases(name=vessel_data.VesselName, ...)` | `aliases.name: SIM VESSEL 0001` | 两者都有可读名称。sample 来自 AIS `VesselName`；generator 为模拟名称。 |
| `aliases.alternateIds` | `AlternateId(id=str(MMSI), type="ALT_ID_TYPE_MMSI_ID")` | 未生成 | generator 需要补充，尤其是 MMSI 作为 alternate id。 |
| `location.position` | `latitude_degrees=vessel_data.LAT`, `longitude_degrees=vessel_data.LON` | `latitudeDegrees`、`longitudeDegrees`、`altitudeHaeMeters` | 两者都有经纬度。sample 没有 altitude；generator 有 `altitudeHaeMeters: 0`。需要确认 mock API 是否接受 altitude。 |
| `milView` | `MilView(disposition="DISPOSITION_NEUTRAL", enviornment="ENVIRONMENT_SURFACE")` | `milView.disposition: ASSUMED_FRIEND`, `milView.environment: SURFACE` | 语义接近但枚举值不同。sample 使用 SDK / API 风格枚举；generator 使用简化值。generator 需要对齐枚举命名。sample 代码里参数名是 `enviornment`，看起来是 SDK 示例中的拼写。 |
| `ontology` | `template="TEMPLATE_TRACK"`, `platform_type="Surface Vessel"` | `template: TEMPLATE_TRACK`, `platformType: SURFACE_VESSEL`, `specificType: SURFACE_VESSEL` | template 一致。platform type 表达不同：sample 是 `"Surface Vessel"`，generator 是 `"SURFACE_VESSEL"`。generator 可能需要支持 sample 风格。 |
| `provenance` | `data_type="vessel-data"`, `integration_name="ais-sample-integration"`, `source_update_time=now` | `dataType: SIMULATED_SURFACE_VESSEL`, `integrationName: local-entity-generator`, `sourceUpdateTime: now` | 字段结构一致，值不同。generator 可增加配置化 integrationName / dataType。 |
| `expiryTime` | `expiry_time=now + 10 seconds` | `expiryTime=now + 1 hour` | 两者都有过期时间。sample 适配实时刷新，过期窗口短；generator 适配离线测试，窗口长。mock 实时发布时建议使用短 TTL 参数。 |
| `isLive` | `is_live=True` | `isLive: True` | 一致。 |
| `createdTime` | `created_time=now` | 未生成 | generator 需要补充，便于对齐 publish payload。 |
| `description` | `"Generated by AIS Vessel Traffic Dataset"` | `"Simulated surface vessel N"` | 两者都有。无需强制一致。 |
| `dataClassification` | `Classification(default=ClassificationInformation(level="CLASSIFICATION_LEVELS_UNCLASSIFIED"))` | 未生成 | generator 可补充本地非敏感 classification 字段。 |

## 第 1 步 Generator 需要补充或调整的字段

建议后续在 `generate_entities.py` 中补充或调整：

- 增加 `createdTime`，与 sample app 的 publish 参数对齐。
- 增加 `aliases.alternateIds`，至少支持 MMSI：
  - `id`
  - `type: ALT_ID_TYPE_MMSI_ID`
- 增加可选 `mmsi` 输入或生成策略，让 `entityId` 可以使用 `str(MMSI)` 或 `sim-mmsi-...`。
- 增加可配置 `provenance.integrationName` 和 `provenance.dataType`。
- 调整或兼容 `milView` 枚举值：
  - sample: `DISPOSITION_NEUTRAL`
  - sample: `ENVIRONMENT_SURFACE`
  - 当前 generator: `ASSUMED_FRIEND` / `SURFACE`
- 调整或兼容 `ontology.platformType`：
  - sample: `Surface Vessel`
  - 当前 generator: `SURFACE_VESSEL`
- 增加 `dataClassification.default.level`，本地可用 `CLASSIFICATION_LEVELS_UNCLASSIFIED`。
- 将 `expiryTime` TTL 参数化。离线 JSON 可继续默认 1 小时；模拟实时 publish 时可使用 10 秒或更短窗口。

## 当前不运行真实 API 的原因

本步骤不运行 `python src/main.py --config var/config.yml`，原因是：

- `src/main.py` 会创建真实 `Lattice` client。
- `src/integration.py` 会调用 `self.lattice.entities.publish_entity(...)`。
- `var/config.yml` 需要真实 endpoint、client id、client secret 和 sandbox token。
- 运行后可能向真实 Lattice 环境发布 entity。
- 当前目标是本地静态分析和字段对齐，不需要真实网络调用。

因此本步骤没有创建 `.env`，没有填入真实凭据，没有请求 Lattice token，也没有调用 Anduril endpoint。

## 下一步如何改造为本地 Mock API 测试

下一步可以在不修改 Anduril sample app 业务逻辑的前提下，围绕本地 generator 和 mock server 做测试：

1. 在本仓库新增本地 mock API，例如 `POST /entities/publish` 或兼容一个简化的 `publish_entity` 接收端。
2. 让第 1 步 generator 产出更接近 sample app 的 entity JSON，包括 `createdTime`、`aliases.alternateIds`、`dataClassification` 和 sample 风格枚举值。
3. 编写一个本地 publish adapter，把 generator 输出的 JSONL 逐条 POST 到 mock API。
4. mock API 只记录和校验 payload，不转发到 Anduril endpoint。
5. 增加字段校验：
   - `entityId` 必填且唯一。
   - `aliases.name` 必填。
   - `location.position.latitudeDegrees` 和 `longitudeDegrees` 在合法范围内。
   - `isLive` 为布尔值。
   - `expiryTime` 和 `provenance.sourceUpdateTime` 是合法 UTC 时间。
6. 后续如果需要对齐 sample app，可通过依赖注入或 wrapper 替换 `Lattice` client，但不要直接改动 `external/sample-app-ais-integration-rest` 的业务源码。

这样可以先验证本地 entity payload 的结构、字段映射和发布流程，再决定是否进入真实 Lattice/Sandbox 联调。
